# Reproduce `domain-randomized-v1`

This directory separates two claims that should not be conflated:

1. **Exact paper inference:** download the frozen `model.ckpt` and `feat_stats.npz`, then verify
   their byte counts and SHA-256 digests against `../manifest.json`.
2. **Training reproduction:** rerun the frozen simulation, preprocessing, training, and
   metric-based selection design. GPU kernels are not promised to be bitwise identical across
   hardware and library builds, so a scientifically equivalent retrain can have a different
   checkpoint hash.

`workflow.json` is the machine-readable specification. It records every known simulation prior,
seed range, feature view, optimizer setting, selection rule, and the exact released hashes. The
historical validation directory was generated by the original CLI starting at seed zero, so its
400 seeds overlap the first 400 training seeds. This validation score is retained only to reproduce
the historical epoch-selection procedure; the paper's performance claims use separate held-out
benchmarks.

## Verify or package the exact paper model

```bash
python3 scripts/verify_model_release.py \
  --model-id domain-randomized-v1 \
  --checkpoint model.ckpt --stats feat_stats.npz

python3 scripts/package_model_release.py \
  --model-id domain-randomized-v1 \
  --checkpoint model.ckpt --stats feat_stats.npz \
  --output domain-randomized-v1.zip

python3 scripts/verify_model_release.py \
  --model-id domain-randomized-v1 \
  --archive domain-randomized-v1.zip
```

The package command is deterministic and embeds `SHA256SUMS`. It refuses any checkpoint or
statistics file that differs from the paper manifest.

## Submit a complete Betty retrain

The compatibility entry point `scripts/dr_train.sh` delegates here. It only submits Slurm jobs;
simulation, preprocessing, training, and selection all execute in allocations. Use a new output
directory because the workflow refuses to mix runs.

```bash
export MODEL_ROOT=/vast/projects/smathi/cohort/$USER/fastrho-model-reproduction
export FASTRHO_PYTHON=/path/to/cuda/environment/bin/python
scripts/dr_train.sh
```

The four numbered stages are:

| Stage | Script | Result |
|---:|---|---|
| 00 | `slurm/00_simulate.sbatch` | 15,000 training and 400 historical-validation regions, sharded across CPU jobs |
| 01 | `slurm/01_preprocess.sbatch` | aligned `hap`, `gt`, and `gtf` shards for both splits |
| 02 | `slurm/02_train.sbatch` | 55-epoch GPU run, all epoch checkpoints, exact metrics CSV, environment capture |
| 03 | `slurm/03_select.sbatch` | checkpoint chosen by maximum exact `val_pearson`, with an immutable JSON record and checksums |

The final record is `${MODEL_ROOT}/release/reproduction-selection.json`; the job graph and job IDs
are in `${MODEL_ROOT}/submission.tsv`. Compare a retrain to the paper artifact scientifically on
the frozen held-out benchmarks, not by expecting a bitwise-identical GPU checkpoint.
